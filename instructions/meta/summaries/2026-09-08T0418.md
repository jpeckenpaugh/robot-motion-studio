# Session Report — Browser Edition

- **Date:** 2026-09-08
- **Executor:** Stage Manager (directed build)
- **Branch:** `main`
- **Work:** `browser-edition/` — a browser-only build hostable on GitHub Pages

## Context

The human asked for a "browser only" implementation of the Robot Motion
Designer that can be hosted directly on GitHub Pages, modeled on the
`poc-browser/` alternative build in the `executive-assistant` repo. The name
chosen for the build is **`browser-edition`**.

Because this app's frontend is already a static SPA with a single API seam
(`window.API`), the port was much cleaner than the exec-assistant port (which
had to rewrite a Jinja-rendered UI): the entire SPA (views, timeline editor,
simulator, motion.js) carried over unchanged except the transport layer.

## What was built

- `browser-edition/` — self-contained static app (no backend, no build step).
- **SQLite in a Web Worker** via vendored `sql.js` (WASM); persistence to the
  browser's **OPFS** (`WorkspaceStorage`).
- **Faithful port** of the backend domain logic to JS under
  `browser-edition/js/db/`: `schema.js` (DDL + revision + validation),
  `seed.js` (door durability rig), `pulse.js`, `validation.js` (error codes),
  `preview.js` (speed/easing/loop math), `export.js` (schema v2), `handlers.js`
  (mirrors all FastAPI routers), `worker.js` (classic worker + request router
  + write transaction/persist), `engine.js` (query helpers), `client.js`
  (main-thread RPC), `persistence.js` (OPFS).
- **Drop-in `api.js`**: preserves `window.API.get/post/put/patch/del` and error
  shapes `{status, code, detail}`; only the export view's download path changed
  (Blob download instead of `Content-Disposition` HTTP).
- **Workspace view** (browser-only): status, export/import `.db`, reset sample
  (re-seed only when empty, mirroring server seed-once semantics).
- `serve.py` (dev static server), `README.md`, `docs/contract.md`,
  `tests/` (Node parity + headless Chrome smoke + reload persistence).

## Verification

- `tests/run.mjs` — **18/18 Node parity checks** pass (schema, seed, preview
  timing + group/sequence repeats, export v2 + filenames, CRUD, guards,
  GROUP_SPLIT, SPEED_DURATION_MISMATCH, reorder, DB round-trip).
- `tests/headless.mjs` — Chrome CDP end-to-end pass: worker boots + seeds the
  Door Durability Rig, SPA renders, worker-backed CRUD + 409 error shape +
  export + workspace status all correct.
- `tests/reload.mjs` — OPFS persistence confirmed across a hard reload.
- Timeline editor renders (600 step elements), simulator draws a canvas.
- No console errors.

## Key decisions

- Reused the entire frontend SPA; only `api.js` replaced (plus a workspace
  view + export download patch). Maximal reuse, minimal delta.
- Worker is a **classic** worker (`importScripts` for sql.js) with dynamic
  `import()` for its own ES modules — matches the proven exec-assistant pattern
  and works on GitHub Pages.
- **Writes commit to OPFS only after a successful transaction** — a real bug
  caught during verification (initially only import/reset persisted); fixed so
  `request` writes wrap in BEGIN/COMMIT + `persist()`.
- Query-string `?robot_id=` handled in the worker router with numeric coercion.
- Error codes and shapes ported 1:1 so `UI.renderApiError` shows `detail (code)`.

## Known limitations

- Single-tab; OPFS is per-origin and clearable — documented, with Export backup
  promoted in the Workspace view.
- `file://` may be an insecure context for OPFS; README notes localhost/https.
- The server edition's known issue G7 (stale `speed_deg_per_s` after a step
  mutation) is ported as-is (same derivation rules).
- Browser checks are headless-Chrome CDP, not a full browser automation harness.
